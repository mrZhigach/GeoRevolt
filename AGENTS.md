# Агентная дисциплина проекта GeoRevolt (v2.0)

**Приоритет:** Данные правила имеют высший приоритет для всех агентов.  
**Контекст:** Проект сочетает децентрализованные рынки предсказаний (AMM, Polygon Amoy) и геопространственную карту (PMTiles, MapLibre GL JS). Стек: Next.js 14 (App Router) + Foundry + SQLite + wagmi/viem.

## 1. Стандарты документирования (инженерный уровень)

### 1.1. Планирование и трекинг (`PLAN.md`, `ROADMAP.md`)

- **`PLAN.md`** – оперативный спринт (макс. 2 недели).  
  **Обязательные столбцы:** `ID`, `Задача`, `Статус [ ]/[~]/[x]/[!]`, `Агент`, `Дедлайн`, `Комментарий`.  
- **`ROADMAP.md`** – стратегический план на 3–6 месяцев с вехами и бизнес‑метриками (создаётся отдельно при необходимости).
- **Ответственный:** `@project-planner` обновляет оба файла ежедневно в 18:00 UTC (или после каждого значимого события).
- **Блокер `[!]`** – автоматически инициирует создание задачи в `CHANGELOG.md` с пометкой `### Blocked`.

### 1.2. Управление изменениями (`CHANGELOG.md` – стандарт Keep a Changelog)

**Структура обязательна:**
```markdown
## [YYYY-MM-DD] – Sprint X – Day Y

### Added
- ...

### Changed
- ...

### Fixed
- ...

### Technical Debt
- ...

### DevOps / Infrastructure
- ...
```

**Правила:**
- Каждый PR или коммит, меняющий логику, добавляет строку.
- Агент, сделавший изменение, обязан добавить запись **до** закрытия задачи.

### 1.3. Журнал тестирования (`TEST_REPORT.md`)

**Содержит не только PASS/FAIL, но и метрики:**
- Процент покрытия кода (lines/branches).
- Gas consumption для смарт‑контрактов.
- Время ответа API (перцентили).
- Ссылки на логи упавших тестов.

**Формат:**
```markdown
# Регрессионный отчёт – Sprint X (YYYY-MM-DD)

## Unit тесты (Foundry)
- Покрытие: ...%
- Газ профиль: ...
- Упало: ... (список)

## Интеграционные тесты (API + SQLite)
- Маршруты: ... PASS/FAIL

## E2E (карта + MetaMask)
- Сценарии: ...

## Инструментарий
- Команда запуска: ...
- CI статус: ...
```

### 1.4. Реестр артефактов (`ARTIFACT_LOG.md`)

**Фиксирует всё, что не входит в репозиторий (контракты, PMTiles, Docker‑образы, миграции).**
**Обязательны:** версия, контрольная сумма (SHA256/MD5), дата создания/деплоя, местонахождение.

Пример для смарт‑контракта:
```markdown
| Контракт | Версия | Bytecode hash | Адрес (сеть) | Дата деплоя |
|----------|--------|---------------|---------------|-------------|
| MarketFactory | 1.2.0 | 0x7f83... | 0x9A7...E3f (Amoy) | 2025-05-11 |
```

## 2. Автоматизация контроля для агентов

Перед закрытием задачи агент **обязан** выполнить скрипт:
```bash
scripts/validate-docs.sh
```
Если скрипт возвращает ошибку – задача не может быть закрыта.

## 3. Правила для отдельных ролей

- `@feature-lead` – создаёт `PLAN.md` в начале спринта, следит за статусами.
- `@project-planner` – ежедневно синхронизирует `PLAN.md` с реальным прогрессом.
- `@qa-automation-engineer` – запускает тесты после каждого изменения и обновляет `TEST_REPORT.md`.
- `@archivist` – проверяет `ARTIFACT_LOG.md` перед каждым релизом и деплоем.
- `@smart-contract-dev` – при деплое нового контракта обязан внести запись в `ARTIFACT_LOG.md` и `CHANGELOG.md`.
- `@cartography-engineer` – после генерации PMTiles фиксирует MD5 и размер в `ARTIFACT_LOG.md`.

## 4. Пример работы агента

1. Пользователь: *«Начинаем задачу #13 – виджет покупки»*
2. `@frontend-dev` переводит задачу в статус `[~]`, обновляет `PLAN.md` (дата начала).
3. Пишет код, тесты.
4. Обновляет `CHANGELOG.md` (секция Added / Changed).
5. Запускает тесты → обновляет `TEST_REPORT.md`.
6. Выполняет `scripts/validate-docs.sh`.
7. Переводит задачу в `[x]`, фиксирует дату завершения в `PLAN.md`.
8. Сообщает: *«Задача #13 выполнена, документация обновлена»*.
